# RPGBattlePrototype 项目开发总结

> 项目名称：RPGBattlePrototype
> 引擎版本：Unreal Engine 5
> 核心框架：GAS + Behavior Tree
> 开发周期：2026.07.25 — 2026.08.15（共21天，累计约85h）
> 文档版本：V1.1（2026.08.16，试玩后修订）

---

## 1. 项目概述

这是一个 1v1 近战 Boss 战战斗原型，基于 UE5 的 GAS 和 Behavior Tree 开发。

项目周期约三周，目标是产出一个可稳定运行的 Boss 战 Demo，包含完整的玩家战斗系统、Boss AI 系统，以及数据驱动的战斗参数配置。开发过程通过每日 DevLog 完整记录。

### 核心亮点

- **完整的 GAS 战斗闭环**：属性集在 C++ 中定义（含 Clamp），Ability 覆盖连招/Dash/E/Q/空中攻击，GE 管理伤害/恢复/CD/无敌，Tag 驱动状态控制，全链路跑通。
- **数据驱动的技能配置**：Excel → CSV → DataTable，通过 SkillID 统一管理 Cooldown、Cost、Damage、CameraShake 等级，新增技能无需修改蓝图逻辑。
- **行为树与 GAS 协同的 Boss AI**：三段距离决策 + 随机技能释放 + CD 状态查询 + 转阶段技能解锁，并针对全技能 CD 场景设计了近距离兜底与主动接近逻辑。

## 3. 核心系统实现

### 3.1 玩家系统

#### 四段普通攻击连招

- 基于 Montage 顺序播放，攻击窗口内缓存输入，跳跃状态屏蔽攻击，窗口外索引自动归零。
- **设计意图**：连招窗口 + 输入缓存是动作游戏手感的底层保障。窗口内可衔接、窗口外归零，既保证了连段流畅性，又避免了"无脑连按永远能接上"的廉价感。跳跃屏蔽攻击则是对状态冲突的最小化处理——空中行为和高干扰地面的攻击体系在逻辑上必须互斥，早期用 Tag 屏蔽而不是复杂状态机，是为了先跑通再迭代。

#### 空中攻击

- 独立 Ability 实现，落地后 Tag 清除逻辑已修复（Day 19）。
- **设计意图**：空中攻击不是"地面攻击的空中版"，而是独立 Ability。原因在于两者的碰撞检测流程、动画 Notify 触发时机和落地后的状态清理路径完全不同。独立 Ability 让空中攻击的 Tag 生命周期和地面攻击彻底解耦，Day 7-9 的碰撞互扰问题正是这一设计决策的验证。

#### Dash

- 最高行为优先级，可打断除跳跃外所有动作，消耗体力，含无敌帧。
- **设计意图**：Dash 的优先级设计是整体战斗状态的"逃生阀"。无论玩家当前处于攻击、受击还是待机状态，Dash 必须可靠响应。"可打断除跳跃外所有动作"的边界选择是基于测试反馈：跳跃本身已经是位移行为，Dash 打断跳跃会造成位置判定混乱，因此将跳跃设为唯一豁免项。

#### 完美闪避

- 触发后慢放 + 画面变灰 + 音效，回复 HP/MP/Strength。
- **设计意图**：完美闪避是对 Dash 无敌帧的"风险升级"。普通 Dash 消耗资源换取安全，完美闪避则要求玩家在攻击判定窗口内精确时机使用 Dash，成功后回复资源形成正向循环。这一机制对应樱井理论中的"压力释放"——高风险高回报的窗口设计让闪避从纯粹的防御行为升级为一种进攻性选择。

#### E/Q 技能

- 消耗 MP，受 Cooldown 限制，空中与跳跃状态禁用。
- **设计意图**：CD 与 Cost 双重限制是动作游戏技能循环的经典结构。CD 管"短期节奏"（不能连续释放），Cost 管"长期策略"（不能无限循环）。两者并存让玩家的资源管理决策从"什么时候放"升级为"这个技能在当前 MP 和 CD 状态下值不值得放"。

#### 属性系统

- HP/MP/Strength 属性集在 C++ 中定义，含 Clamp 限制，MP 与 Strength 通过 GE 自动恢复。
- **设计意图**：属性集放在 C++ 层而非蓝图，是"数据与逻辑归 C++，表现归蓝图"原则的第一次落地。Clamp 不是防御性编程的洁癖，而是 GAS 中 GE 多来源叠加时属性越界的真实风险——一旦越界，后续所有基于百分比的 UI 和逻辑都会连锁出错。

#### 死亡与重生

- 播放死亡动画，延迟后重生，Dash 可打断重生动画，含存档点机制。

### 3.2 Boss 系统

#### 技能体系

- 7 个技能，含 6 个常态技能与 1 个转阶段解锁技能。
- **设计意图**：技能数量不是堆料，而是"覆盖不同距离区间 + 不同节奏压力"的最小集合。6 个常态技能分布在近/中/远三段距离上，确保 Boss 在任何相对位置都有可执行的行为；转阶段解锁技能作为二阶段的"新威胁信号"，让玩家在第一阶段建立的安全感在第二阶段被打破。

#### 攻击判定

- 因无武器模型，采用 Multi Sphere Trace By Channel 构建圆柱形攻击区域，解决贴脸漏判问题。
- **设计意图**：Boss 攻击判定与 Player 武器碰撞是两条独立管线。选择 Multi Sphere Trace 而非传统碰撞体，是因为 Boss 体型大、攻击范围不规则，双插槽圆柱形区域能更精确地控制判定空间的形状，且后续调整攻击范围只需改参数不需改模型。

#### 行为树 AI

- 基于三段距离区间（近/中/远）决策，技能随机释放，Cooldown 由 GAS 管理。
- **设计意图**：距离分区是"让 AI 看起来有意图"的最小架构。近/中/远三个区间各自绑定不同技能组，意味着 Boss 的行为不是随机游走，而是随着玩家位置变化做出可预期的战术调整。技能随机释放则避免固定顺序带来的"背板感"，与 CD 管理的结合让随机性呈现在合理范围内。

#### Cooldown 兜底逻辑

- 近距离攻击设为 0 Cooldown，防止全部技能进入 CD 时 Boss 原地发呆；中远距离技能全部 CD 时通过 MoveTo 主动接近玩家。
- **设计意图**：这是 Demo 中最重要的 AI 体验保障设计。行为树决策层和 GAS 技能状态层的交互最容易出现的 Bug 不是"技能放不出来"，而是"没技能可放时行为树没有任何默认行为"。0 CD 近战技能作为绝对兜底，确保 Boss 在任何状态下都有最小可用行为。

#### 转阶段机制

- Boss HP 首次低于 50% 时触发，播放咆哮动画期间无敌，动画结束后 BGM 切换、移速提升、解锁新技能。
- **设计意图**：转阶段不是简单的数值变化，而是多层反馈同步触发：视觉（咆哮动画+无敌）→ 听觉（BGM 切换）→ 机制（新技能解锁）→ 节奏（移速提升）。这种多层次同步切换让玩家在瞬间感知到"战斗规则变了"，这是动作游戏转阶段设计的核心方法。

#### 目标锁定与转向

- 鼠标中键锁定 Boss，使用 RInterp 实现平滑转向。

#### 死亡演出

- 死亡 Montage → 倒地瞬间切换至 Ragdoll → 延迟 2 秒弹出胜利 UI。
- **设计意图**：延迟弹出胜利 UI 是演出节奏的关键。2 秒窗口让死亡动画完整播放，避免 UI 弹出打断演出高潮。Montage → Ragdoll 的组合则是为了兼顾"设计的死亡表现"与"物理真实感"——前者保证演出可控性，后者提供每一次击杀的微小差异。

### 3.3 数据驱动架构

- 所有技能的 Cooldown、Cost、Damage、CameraShake 等级统一由 Excel 管理。
- 数据管线：Excel → CSV → DataTable → 蓝图通过 SkillID 查询读取。
- 新增技能只需在 Excel 新增一行数据，无需修改蓝图逻辑。
- **设计意图**：数据驱动不是工程洁癖，而是"策划友好"的直接实现。技术策划的核心职责之一是让数值调整不依赖程序改动。DataTable 管线的建立意味着：试玩后如果发现某个技能伤害过高，改一行 Excel 即可，不需要打开蓝图编辑器。

### 3.4 战斗反馈系统

- 伤害数字飘字（含 30% 暴击概率，暴击拥有独立颜色与飘字动画）
- CameraShake 分级（Light/Medium），通过 DataTable 配置
- 受击音效分级（普通/重受击）、死亡音效、完美闪避音效
- 开场 BGM + Boss 半血转阶段时 BGM 切换
- Boss 血条、Player 属性条、技能 CD 填充显示、开始/操作说明/暂停/胜利/失败界面

### 主要踩坑记录

**1. Day 7–9 碰撞互相影响（耗时3天）**
- **现象**：空中攻击接入后，地面攻击与空中攻击的伤害判定同时出现问题。
- **根因**：多 Ability 共用底层碰撞检测流程时，未做调用来源隔离。修改一处碰撞参数影响到了另一条链路。
- **收获**：共享逻辑需要显式区分调用来源，不能假设局部修改不影响全局。这一认知直接影响了后续架构决策——空中攻击和地面攻击分别维护独立 Tag 生命周期，数据驱动层用 SkillID 区分不同技能的参数来源。

**2. Day 13–16 CD 未进入行为树判断（耗时4天）**
- **现象**：Boss 技能 CD 在 GAS 层面已生效，但行为树查询时未正确获取 CD 状态，导致随机释放逻辑异常。
- **根因**：行为树与 GAS 之间的数据交互链路不完整，Cooldown 状态未传递至决策层。各模块单独运行正常不代表整体流程正确。
- **收获**：跨模块数据流是联调阶段的首要排查目标。重写随机 Task 后，CD 状态查询链路打通，也衍生出了后续"全 CD 兜底"的设计。

**3. Day 17 E/Q 技能空中释放异常**
- **现象**：空中释放时不消耗 MP、不播放动画，但仍进入 CD。
- **根因**：释放条件校验逻辑不完整，部分分支未拦截异常调用。
- **收获**：Abort 路径的条件判断需要覆盖所有边界状态，不能只测"正常路径"。

**4. Day 19 空中攻击 Tag 残留**
- **现象**：空中攻击落地后立即 Dash，导致攻击 Tag 未被清除，后续操作异常。
- **根因**：Tag 清除时机绑定在动画结束事件上，落地后 Dash 打断了动画但未触发清除逻辑。
- **收获**：Tag 生命周期应绑定到 Ability 实例的生命周期（OnCanceled/OnInterrupted），而非动画事件。这一教训已转化为 NEXT_STEPS.md 中的 T3 优化项。

### 已知问题（待修复，编号与 NEXT_STEPS.md 一致）

**Bug 1：Boss 行为树技能中断异常（高）**
- **现象**：Player 切换距离时，Boss 中断当前正在释放的技能，转而释放其他技能。
- **根因分析**：行为树使用了 lower priority 机制，距离条件变化导致高优先级分支抢占当前执行中的技能。不设置该机制则 Boss 会移动到 Player 面前才释放远程技能，违背设计目的。
- **已尝试方案**：将距离条件从大到小排列，中断频率有所降低但未完全解决。
- **解决方向**：引入技能决策锁机制（详见 NEXT_STEPS.md T1）。Boss 进入技能执行阶段后，短时间内锁定当前决策，距离变化只影响下一次技能选择。

**Bug 2：完美闪避判定异常（中）**
- **现象**：Boss 二阶段变球技能释放时，即使 Player 距离 Boss 很远，闪避仍触发完美闪避。
- **根因分析**：暂未定位。推测为变球技能的攻击判定范围或闪避检测窗口存在边界条件错误。变球技能本身存在碰撞与物理解算问题（低摩擦惯性、旋转冲突、速度矢量方向丢失），完美闪避的触发检测可能依赖了这些异常状态。
- **解决方向**：排查变球技能判定逻辑与完美闪避触发条件的交互关系（详见 NEXT_STEPS.md T1 附表）。

**Bug 3：胜利 Tag 异常挂载（低）**
- **现象**：战斗中偶发挂载本应胜利时才挂载的 Tag。
- **根因分析**：暂未定位，推测为 Tag 赋予条件在某些边缘情况下被误触发。
- **已尝试方案**：暂时取消了 Player 技能不能含有此 Tag 时释放的限制，表现恢复正常。副作用为胜利动作仍可能被打断，影响较小。
- **解决方向**：Tag 状态管理规范化（详见 NEXT_STEPS.md T2）。

**Bug 4：打包后分辨率异常（低）**
- **现象**：打包后项目分辨率与编辑器内不一致。
- **根因分析**：暂未定位。可能为项目设置或打包配置问题。
- **解决方向**：检查 Project Settings 分辨率与打包配置。

以上问题均不阻塞 Demo 演示，将在后续迭代中修复。

## 8. 总结

三周开发中最大的收获是对 GAS 与行为树协同架构的理解——技能状态由 GAS 管理、决策逻辑由行为树驱动，两者通过黑板和 Tag 通信，联调阶段的多数 Bug 本质上都是跨模块数据流不完整。

同时也体会到战斗 Demo 的核心不是功能数量，而是打击感反馈的完整度。V1.0 证明了战斗闭环可行，V1.1 的迭代方向已经从"能不能打"转向"打起来爽不爽"——这是两个完全不同的问题。

**试玩反馈验证了这一点：** 8.16 朋友试玩后，最直接的反馈集中在"Boss 被打没反应"（受击僵直缺失）和"Boss 技能突然变了"（行为树中断 Bug）上。玩家的第一感知永远是表现层和 AI 合理性，而非架构优雅度。这对后续迭代的优先级排序有直接的指导意义。
