# RPGBattlePrototype 项目开发总结

> 项目名称：RPGBattlePrototype
> 引擎版本：Unreal Engine 5
> 核心框架：GAS + Behavior Tree
> 开发周期：V1.0 2026.07.25 — 2026.08.15（21天）+ V1.1 2026.08.17 — 2026.08.20（4天），累计约105h
> 文档版本：V1.2（2026.08.21）


## 1. 项目概述

这是一个 1v1 近战 Boss 战战斗原型，基于 UE5 的 GAS 和 Behavior Tree 开发。

V1.0 开发周期约三周，目标是产出一个可稳定运行的 Boss 战 Demo，包含完整的玩家战斗系统、Boss AI 系统，以及数据驱动的战斗参数配置。V1.1 基于试玩反馈进行了为期六天的迭代修复，修复了全部已知 Bug，并补充了血条缓动、受击粒子等体验优化。开发过程通过每日 DevLog 完整记录。

### 核心亮点

- **完整的 GAS 战斗闭环**：属性集在 C++ 中定义（含 Clamp），Ability 覆盖连招/Dash/E/Q/空中攻击，GE 管理伤害/恢复/CD/无敌，Tag 驱动状态控制，全链路跑通。
- **数据驱动的技能配置**：Excel → CSV → DataTable，通过 SkillID 统一管理 Cooldown、Cost、Damage、CameraShake 等级，新增技能无需修改蓝图逻辑。
- **行为树与 GAS 协同的 Boss AI**：三段距离决策 + 随机技能释放 + CD 状态查询 + 转阶段技能解锁，并针对全技能 CD 场景设计了近距离兜底与主动接近逻辑。

## 3. 核心系统实现

### 3.1 玩家系统

#### 四段普通攻击连招

- 基于 Montage 顺序播放，攻击窗口内缓存输入，跳跃状态屏蔽攻击，窗口外索引自动归零。
- **设计意图**：连招窗口 + 输入缓存是动作游戏手感的底层保障。窗口内可衔接、窗口外归零，既保证了连段流畅性，又避免了"无脑连按永远能接上"的廉价感。跳跃屏蔽攻击则是对状态冲突的最小化处理。

#### 空中攻击

- 独立 Ability 实现，落地后 Tag 清除逻辑已修复（V1.0 Day 19）。
- **设计意图**：空中攻击与地面攻击的碰撞检测流程、动画 Notify 触发时机和状态清理路径完全不同，独立 Ability 让两者的 Tag 生命周期彻底解耦。

#### Dash

- 最高行为优先级，可打断除跳跃外所有动作，消耗体力，含无敌帧。
- **设计意图**：Dash 是整体战斗状态的"逃生阀"，无论玩家当前处于攻击、受击还是待机状态，Dash 必须可靠响应。

#### 完美闪避

- 触发后慢放 + 画面变灰 + 音效，回复 HP/MP/Strength。
- **设计意图**：完美闪避是对 Dash 无敌帧的"风险升级"——高风险高回报的窗口设计让闪避从纯粹的防御行为升级为一种进攻性选择。

#### E/Q 技能

- 消耗 MP，受 Cooldown 限制，空中与跳跃状态禁用。
- **设计意图**：CD 与 Cost 双重限制是动作游戏技能循环的经典结构——CD 管短期节奏，Cost 管长期策略。

#### 属性系统

- HP/MP/Strength 属性集在 C++ 中定义，含 Clamp 限制，MP 与 Strength 通过 GE 自动恢复。
- **设计意图**：属性集放在 C++ 层是"数据与逻辑归 C++，表现归蓝图"原则的落地。Clamp 防止 GE 多来源叠加时属性越界。

#### 死亡与重生

- 播放死亡动画，延迟后重生，Dash 可打断重生动画，含存档点机制。

### 3.2 Boss 系统

#### 技能体系

- 7 个技能，含 6 个常态技能与 1 个转阶段解锁技能。
- **设计意图**：技能分布在近/中/远三段距离上，确保 Boss 在任何相对位置都有可执行的行为；转阶段解锁技能作为二阶段的"新威胁信号"。

#### 攻击判定

- 采用 Multi Sphere Trace + Box Trace 混合方案，根据不同技能分别配置对应的检测形状。
- **设计意图**：Boss 体型大、攻击范围不规则，混合检测方案能更精确地控制判定空间的形状，且后续调整只需改参数。

#### 行为树 AI

- 基于三段距离区间（近/中/远）决策，技能随机释放，Cooldown 由 GAS 管理。
- **设计意图**：距离分区是"让 AI 看起来有意图"的最小架构。技能随机释放避免固定顺序带来的"背板感"。

#### Cooldown 兜底逻辑

- 近距离攻击设为 0 Cooldown，防止全部技能进入 CD 时 Boss 原地发呆；中远距离技能全部 CD 时通过 MoveTo 主动接近玩家。
- **设计意图**：确保 Boss 在任何状态下都有最小可用行为。

#### 转阶段机制

- Boss HP 首次低于 50% 时触发，播放咆哮动画期间无敌，动画结束后 BGM 切换、移速提升、解锁新技能。
- **设计意图**：多层反馈同步触发——视觉（咆哮动画+无敌）→ 听觉（BGM 切换）→ 机制（新技能解锁）→ 节奏（移速提升）。

#### 目标锁定与转向

- 鼠标中键锁定 Boss，使用 RInterp 实现平滑转向。

#### 死亡演出

- 死亡 Montage → 倒地瞬间切换至 Ragdoll → 延迟 2 秒弹出胜利 UI。
- **设计意图**：延迟弹出胜利 UI 让死亡动画完整播放，避免 UI 打断演出高潮。

### 3.3 数据驱动架构

- 所有技能的 Cooldown、Cost、Damage、CameraShake 等级统一由 Excel 管理。
- 数据管线：Excel → CSV → DataTable → 蓝图通过 SkillID 查询读取。
- 新增技能只需在 Excel 新增一行数据，无需修改蓝图逻辑。
- **设计意图**：技术策划的核心职责之一是让数值调整不依赖程序改动。DataTable 管线的建立意味着试玩后改数值不需要打开蓝图编辑器。

### 3.4 战斗反馈系统（V1.1 已完善）

- 伤害数字飘字（含 30% 暴击概率，暴击拥有独立颜色与飘字动画）
- CameraShake 分级（Light/Medium），通过 DataTable 配置
- 受击音效分级（普通/重受击）、死亡音效、完美闪避音效
- 开场 BGM + Boss 半血转阶段时 BGM 切换
- **V1.1 新增**：受击粒子（普通/暴击两套）、双层血条缓动
- Boss 血条、Player 属性条、技能 CD 填充显示、开始/操作说明/暂停/胜利/失败界面

### 主要踩坑记录

**1. Day 7–9 碰撞互相影响（耗时3天）**
- **现象**：空中攻击接入后，地面攻击与空中攻击的伤害判定同时出现问题。
- **根因**：多 Ability 共用底层碰撞检测流程时，未做调用来源隔离。
- **收获**：共享逻辑需要显式区分调用来源，不能假设局部修改不影响全局。

**2. Day 13–16 CD 未进入行为树判断（耗时4天）**
- **现象**：Boss 技能 CD 在 GAS 层面已生效，但行为树查询时未正确获取 CD 状态。
- **根因**：行为树与 GAS 之间的数据交互链路不完整，Cooldown 状态未传递至决策层。
- **收获**：跨模块数据流是联调阶段的首要排查目标。

**3. Day 17 E/Q 技能空中释放异常**
- **现象**：空中释放时不消耗 MP、不播放动画，但仍进入 CD。
- **根因**：释放条件校验逻辑不完整，部分分支未拦截异常调用。
- **收获**：Abort 路径的条件判断需要覆盖所有边界状态。

**4. Day 19 空中攻击 Tag 残留**
- **现象**：空中攻击落地后立即 Dash，导致攻击 Tag 未被清除。
- **根因**：Tag 清除时机绑定在动画结束事件上，落地后 Dash 打断了动画但未触发清除逻辑。
- **收获**：Tag 生命周期应绑定到 Ability 实例的生命周期，而非动画事件。

## 8. 总结

V1.0 开发的核心收获是对 GAS 与行为树协同架构的理解——技能状态由 GAS 管理、决策逻辑由行为树驱动，两者通过黑板和 Tag 通信，联调阶段的多数 Bug 本质上都是跨模块数据流不完整。

V1.1 迭代验证了一个重要判断：试玩反馈中最影响体验的往往不是功能缺失，而是表现层和 AI 合理性上的细节问题。Boss 被打没反应、技能突然变招、血条跳变太硬——这些问题的代码量往往不大，但对玩家感知的影响却很大。后续迭代的优先级排序，会继续以“玩家实际感知”作为判断依据。
